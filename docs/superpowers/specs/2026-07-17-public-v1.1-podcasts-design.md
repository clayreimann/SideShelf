# Public v1.1 Podcasts — Design Spec

**Date:** 2026-07-17
**Status:** First increment approved 2026-10-10. The full public 1.1 scope remains the accepted roadmap target; its deferred tier is retained below for later delivery. Partial podcast foundations exist (see [Current State](#current-state)); the first increment is not implemented end to end, and runtime API verification and device qualification are pending.
**Public release:** 1.1 (full contract). The first increment's version label is undecided.
**Playback baseline:** React Native Track Player 4.1.2

---

## Versioning Context

SideShelf used `v1.0` through `v1.3` for internal engineering milestones before its first public release. Those names remain historical planning identifiers. This document uses **public 1.1** for the full podcast contract described here; it is not a promise about the next store version, and the first increment's version label is undecided.

---

## Scope Status

This spec holds two tiers:

- **First increment (approved):** show and episode browsing; episode-aware streaming, progress, resume and restore; manual per-episode download, cancel, retry, delete, and offline playback; played/unplayed state that survives restart and offline use; separate aggregated **Library** (books) and **Podcasts** (shows) tabs for the current server and account.
- **Deferred contract:** Up Next, autoplay, automatic device downloads, and retention. The design for these is kept below and marked **[Deferred]**. None of it is required by the first increment.

Unmarked sections apply to the first increment. Where a section mixes tiers, it says which parts are deferred. Shipping the first increment does not complete public 1.1 and does not close [#21](https://github.com/clayreimann/SideShelf/issues/21).

---

## Goal

Make SideShelf a full-featured mobile client for listening to podcasts that already exist in the user's Audiobookshelf libraries.

The full public 1.1 contract includes show and episode browsing, episode-aware streaming and progress, individual and automatic device downloads, retention controls, played-state management, and a persistent podcast Up Next queue. The first increment delivers the browsing, playback, progress, manual-download, and played-state parts; automatic downloads, retention, Up Next, and autoplay follow later. Both retain RNTP as the local player so neither is gated on the newer Audio Browser dependency.

The release does **not** add podcast discovery, RSS subscription administration, Google Cast, CarPlay, Android Auto, or the Audio Browser migration.

---

## Product Decisions

The following decisions were made during roadmap shaping:

- Podcast libraries already managed by Audiobookshelf are the catalog source.
- Public 1.1 will be a full-featured podcast release, not streaming-only support. It is delivered in increments; see [Scope Status](#scope-status).
- RNTP remains the production playback dependency for public 1.1.
- Work on Audio Browser may proceed as an isolated compatibility/upstream spike, but it cannot block 1.1.

First increment (approved 2026-10-10):

- **Current server and account only.** Aggregation covers the accessible libraries of the signed-in account on the current server. Cross-server aggregation waits on the [multi-server design](../../plans/multi-server-sync-and-aliases.md).
- **Separate tabs, no mixing.** The main **Library** tab shows books and a **Podcasts** tab shows shows. There is no mixed grid and no All/Books/Podcasts filter. Series and Authors stay book-only. Podcasts joins the default tab bar (Home, Library, Podcasts, Series, More) and Authors stays reachable from More; this placement is routine within the approved separate-tabs decision.
- **Mixed surfaces keep episode identity.** Home, Continue Listening, and Downloads may mix books and episodes, keyed by `(libraryItemId, episodeId)` for episodes.
- **Inclusion is exclusions-only.** Each tab stores a persistent per-type exclusion list, scoped to the current server and user. Initially every library is included. A library that becomes accessible later is included automatically. "Select None" excludes the libraries currently known; a library that appears afterwards is included while the earlier exclusions stay. Inclusion never hides downloads, deletes files, or stops playback.
- **Provenance.** Cards show the library name when more than one library of the type is included. Items with identical titles stay distinct, in deterministic order.
- **Book Series versus Podcast Shows.** Books use _Series_; podcasts use _Shows_, _Episodes_, and an optional _Season_ within a show. Seasons are free-form episode metadata strings, never series. Shows and series are never merged by title, podcasts never route through book-series screens, and no cross-show franchise grouping is assumed.
- **Episode order.** Episodes list newest first in every state, with played/unplayed shown on each row and an **Unplayed** filter. The show's `type` is a nullable string (commonly `episodic` or `serial`); unknown values and null are tolerated, shown as display metadata only, and never change the order. The deferred oldest-first option is not ruled out by this default.

Deferred contract:

- Automatic downloads apply to the mobile device, not Audiobookshelf's server-side feed acquisition settings.
- Up Next contains podcast episodes only; audiobooks do not participate.
- The app-owned Up Next queue remains independent of RNTP's native queue.

## Current State

SideShelf already has useful podcast foundations:

- API types for podcasts and episodes.
- Podcast-aware library and metadata persistence for the show itself.
- `episodeId` fields in media progress and listening-session APIs.
- `local_listening_sessions.episode_id` (migration 0016). The progress outbox stays keyed by physical `session_id` and takes the episode from its owning session.
- Episode-aware progress synchronization in parts of `ProgressService`.
- `episodeId` in the coordinator's `LOAD_TRACK` event and `PlayerService.playTrack()` API.
- Podcast fixtures and partial database tests.
- Audiobookshelf library shelves can identify podcast and episode content.

The existing support is partial and not end-to-end:

- Podcast ingestion writes the show item, metadata, genres, and tags only. There is no episode table, and no episode audio files or chapters are persisted.
- There is no episode-list product experience.
- `TrackLoadingCollaborator.executeLoadTrack()` accepts `episodeId` but does not use it when selecting metadata, audio files, or the play endpoint.
- `startPlaySession()` always calls the library-item play endpoint instead of the podcast episode endpoint.
- `LibraryItemDetail` renders the audiobook-oriented chapter, bookmark, audio-file, and whole-item download experience for every media type.
- Downloads and download status are primarily keyed by library item rather than episode.
- `PlayerTrack` cannot fully distinguish an audiobook from a podcast episode.
- There is no app-owned podcast queue, per-show mobile setting, or automatic retention engine (all deferred).

## User Experience

### Library and Podcasts Tabs

The main **Library** tab aggregates the included book libraries; the **Podcasts** tab aggregates the included podcast libraries. Both share the existing library shell, theming, offline behavior, and navigation conventions, and follow the inclusion, provenance, and no-mixing rules in [Product Decisions](#product-decisions).

First increment, both tabs:

- One grid across the included libraries of the tab's media type, with library-name provenance when more than one is included.
- Deterministic global sort and local search across all included sources, not per library: book title, author, narrator, and series on Library; show title and creator on Podcasts.
- Persisted sort per page, scoped to the current server and user.
- Distinct empty states for no accessible libraries, all excluded, no matches, and sync failure. Incomplete or failed sources are labeled, and results are not presented as final until every included source completes.
- On upgrade, the legacy single-library selection does not carry over for visibility: every library starts included. Only the existing book sort preference is copied once into the Library page.

First increment, Podcasts tab only:

- Continue Listening and downloaded episodes surface through Home and Downloads, not a separate podcast shelf.

**[Deferred]:** Recently Added episodes, a downloaded-episodes shelf in the tab, Up Next, and search across episode titles.

Neither tier searches external podcast directories or adds RSS feeds.

### Show Detail

Selecting a show opens a podcast-specific detail screen. First increment:

- Show artwork, title, author, description, genres, and explicit indicator.
- Episode count.
- Episodes newest first in every state, regardless of show type.
- An **Unplayed** filter.
- An episode list that supports pagination or incremental rendering for large feeds.

**[Deferred]:** new/unplayed count, oldest-first sorting, downloaded filter, search within the show, and per-show mobile download and autoplay settings.

The show screen does not display audiobook chapters, audiobook audio-file diagnostics, book series metadata, or item-level bookmark controls.

### Episode Rows and Detail

First increment, each episode exposes:

- Title, publication date, duration, season/episode labels when supplied, and explicit state.
- Description or show notes.
- Played, in-progress, downloaded, and downloading state.
- Play or resume.
- Download, cancel, retry, and delete download.
- Mark played or unplayed.
- "Removed from feed" when the server drops an episode that is downloaded or active.

**[Deferred]:** queued state, Play Next, Add to Up Next, and Remove from Up Next.

An episode may use an inline expansion or a separate detail route, depending on the final UI plan. The behaviors and state model are required regardless of presentation.

### Player

The existing floating and full-screen players remain the primary playback UI. For podcasts they show:

- Episode title as the primary title.
- Podcast/show title and author as secondary metadata.
- Episode artwork with show artwork fallback.
- Episode-relative elapsed time and duration.
- Standard play, pause, seek, skip interval, playback rate, sleep timer, output route, and progress behavior.
- **[Deferred]:** Up Next access and next-episode context.

In the first increment, natural completion of an episode ends playback of that episode and loads nothing else.

Audiobook-only chapter and bookmark affordances are hidden when they do not apply. Episode bookmarks are out of scope unless a stable Audiobookshelf episode-bookmark API is verified during planning.

## Up Next Queue [Deferred]

Not part of the first increment. This section is the later contract.

### Ownership

Up Next is a SideShelf-owned persistent queue. It stores logical episode identity, not RNTP track IDs or streaming URLs.

RNTP's native queue continues to represent the audio file or files belonging to the **currently active media item**. It must not be reused as durable product state for multiple podcast episodes.

### Required Operations

- Add an episode to the end.
- Play an episode next.
- Remove an episode.
- Reorder episodes.
- Clear the queue with confirmation.
- Start playback from any queued episode.
- Automatically remove or mark the active entry when playback completes.
- Skip an unavailable entry and surface a non-blocking error.
- Persist across app restarts and account for the active user/server.

### Playback Rules

- Selecting **Play** starts the chosen episode immediately.
- **Play Next** inserts immediately after the active episode.
- **Add to Up Next** appends without interrupting playback.
- When an episode completes naturally, the next valid queue entry begins.
- Manually stopping playback does not consume the next entry.
- Marking an episode played does not silently remove it from Up Next; queue mutation remains explicit except for natural playback completion.
- Queue entries belonging to a removed library item are pruned during reconciliation.

### Per-show Autoplay

Each show can select:

- Off.
- Next oldest unplayed episode.
- Next newest unplayed episode.

Autoplay resolves and appends the next eligible episode only when the active episode nears or reaches completion. It must not eagerly materialize an entire feed into RNTP or Up Next.

## Device Downloads and Retention

### Manual Downloads

First increment. Users can download, cancel, retry, or delete individual episodes and play them offline. Download identity must include both `libraryItemId` and `episodeId`; whole-show identity is insufficient. Deleting the episode that is playing or loading is refused with an explanation, and deleting one episode never touches its siblings or any book.

**[Deferred]:** Manual downloads are not removed by automatic retention unless the user explicitly opts into that behavior in a later release.

### Automatic Downloads [Deferred]

Per-show settings include:

- Automatic device downloads on/off.
- Maximum number of automatically downloaded episodes to retain.
- Eligibility: newest unplayed episodes by default.
- Optional inclusion of episodes already present when auto-download is first enabled.

Automatic download evaluation runs when episode data is refreshed, including app launch, library synchronization, show refresh, and OS-permitted background refresh. SideShelf does not promise immediate download at feed publication time because the self-hosted server does not push directly to a guaranteed-running mobile process.

### Retention Rules [Deferred]

The retention engine:

1. Considers only episodes downloaded by the automatic policy.
2. Removes played episodes before unplayed episodes.
3. Removes oldest eligible episodes first.
4. Never removes the active episode.
5. Never removes an in-progress download.
6. Never removes an episode protected by a manual download/keep marker.
7. Avoids removing an episode in Up Next; if the configured limit cannot be met safely, it leaves the extra file and records why.

Retention must be deterministic and independently testable.

### Offline Behavior

- Cached show and episode metadata remains browsable offline.
- Downloaded episodes play without contacting Audiobookshelf.
- Streaming-only episodes show a clear unavailable state offline.
- Played state and listening sessions created offline synchronize when connectivity returns. Played state survives app restart and offline use; it is cleared on logout or account switch like other per-account data.
- **[Deferred]:** Queue advancement skips unavailable streaming entries rather than stopping silently.
- **[Deferred]:** Failed automatic downloads remain retryable and do not block manual downloads.

## Data Model

The implementation plan should define exact schemas, but public 1.1 requires these logical entities:

### Podcast Episode

First increment. Durable episode data for the current account, keyed by `libraryItemId` and `episodeId` (never by title, URL, or file index), including:

- Show identity.
- Title and description.
- Publication date.
- Duration.
- Season/episode/type metadata as nullable strings; unknown values are tolerated and never create book series.
- Audio enclosure metadata needed for display and diagnostics.
- Artwork override/fallback data.
- Server availability and last-seen timestamp.

### Library Inclusion

First increment. A per-type exclusion list (books, podcasts) scoped to the current server route and user, plus per-page sort preferences.

### Podcast Queue Entry [Deferred]

- Stable local queue-entry ID.
- User/server scope.
- `libraryItemId` and `episodeId`.
- Sort position.
- Creation time and source (`manual`, `play-next`, or `autoplay`).

### Per-show Mobile Settings [Deferred]

- User/server scope and `libraryItemId`.
- Auto-download enabled.
- Retention count.
- Autoplay policy.
- Optional manual-keep behavior if needed by the download design.

### Episode Download Identity

First increment. Download and file records must distinguish episodes, and download and cover-cache records are owner-scoped to the current server route and user. Existing item-level APIs and selectors should remain valid for audiobooks while podcast-specific helpers expose episode status.

All database operations must use helpers in `src/db/helpers/`; UI and services must not issue inline Drizzle queries.

## API and Synchronization

Audiobookshelf documents separate endpoints for playing a library item and a podcast episode:

```text
POST /api/items/{libraryItemId}/play
POST /api/items/{libraryItemId}/play/{episodeId}
```

Public 1.1 must use the episode endpoint (the documented route, which the F0p play probe must confirm at runtime before implementation relies on it) and preserve `episodeId` through:

```text
UI intent
  -> coordinator LOAD_TRACK
  -> PlayerService
  -> metadata/audio resolution
  -> Audiobookshelf play session
  -> PlayerTrack/current media
  -> listening session
  -> progress synchronization
```

The client also needs verified endpoint wrappers for:

- Podcast/show detail with episodes.
- Episode-specific media progress.
- Mark played/unplayed. No route is assumed; the episode mutation must be observed at runtime first.
- Play-session update and close behavior for episodes.
- **[Deferred]:** Recent episodes or equivalent paginated retrieval.

The published Audiobookshelf API reference warns that it is out of date. Endpoint behavior must be verified at runtime before dependent implementation; see [Prerequisites and Delivery](#prerequisites-and-delivery).

Source:

- [Audiobookshelf API reference — Play a Library Item or Podcast Episode](https://api.audiobookshelf.org/)

## Playback Architecture

### Media Identity

The player model must explicitly represent:

- `mediaType: "book" | "podcast"`.
- `libraryItemId`.
- `mediaId`.
- `episodeId` for podcasts.
- Stable logical identity independent of a local path or expiring stream URL.
- Display metadata appropriate to the media type.

### Coordinator Ownership

The existing rule remains unchanged: the coordinator decides; player services execute and report facts.

Podcast support adds episode identity without adding direct RNTP calls to UI, queue storage, or download code. Same-media checks compare `(libraryItemId, episodeId)`, so switching between sibling episodes reloads. Natural episode completion enters the coordinator as a factual event. In the first increment the coordinator loads nothing next. **[Deferred]:** queue-advance events, where the coordinator or a dedicated queue coordinator decides whether to load the next episode.

### Queue Separation [Deferred]

```text
PodcastQueueService (durable episode intent)
    -> coordinator selects active episode
        -> PlayerService builds current episode media
            -> RNTP queue contains only that episode's file(s)
```

This boundary is also suitable for the future Audio Browser migration without making public 1.1 depend on it.

## Error Handling

- A failed stream session offers retry/download actions.
- A deleted server episode does not erase listening history, progress, or downloads; reconciliation records that the source disappeared.
- An explicit played/unplayed toggle is stored as a durable local intent that overrides the displayed server state while pending; delivery is revision-guarded so a newer toggle is never lost, and once acknowledged the server is authoritative again.
- If episode metadata is incomplete, stable IDs and safe fallback titles are used; the episode is not keyed by title or URL.
- **[Deferred]:** A missing episode is marked unavailable and skipped when reached through Up Next.
- **[Deferred]:** A failed stream session preserves the queue.
- **[Deferred]:** Download retention failures never delete unverified paths and never prevent playback.
- **[Deferred]:** Automatic-download failures are isolated per episode.

- Played/unplayed transitions.

## Acceptance Criteria

Qualification against these criteria is pending. The full public 1.1 release requires both lists.

### First Increment

1. Users can browse every accessible podcast show on the current server and account in a Podcasts tab separate from the book Library tab, subject to the inclusion rule, with provenance when more than one library is included.
2. The Library tab aggregates the included book libraries with deterministic global sort and search across sources, provenance when more than one library is included, and a persisted per-page sort.
3. Inclusion follows the exclusions-only rule and persists across restart, scoped to the current server route and user.
4. Incomplete or failed sources are labeled on both tabs, and results are not presented as final until every included source completes.
5. An episode can stream, download, play offline, resume, and synchronize progress using its correct `episodeId`.
6. Played/unplayed state is accurate locally and on the server, and survives restart and offline use (not logout or account switch).
7. No catalog, episode, progress, played-state, download, or cover data from one account is visible or writable after logout or an account or server change.
8. Upgrading a 1.0 install preserves book downloads, listening sessions, the progress outbox, and bookmarks. A failed migration is non-destructive and never resets the database automatically.
9. Audiobook playback, downloads, progress, chapters, bookmarks, and restoration do not regress.
10. Background playback and app-killed restoration pass on physical iOS and Android devices.
11. Offline listening and delayed sync pass end-to-end.
12. No production code depends on Audio Browser or Google Cast.

### Deferred Contract

These were criteria 4–6 of the original single-release list.

1. Up Next persists, reorders, advances naturally, and recovers after restart.
2. Per-show autoplay follows the selected ordering without duplicating entries.
3. Device auto-download discovers eligible episodes during refresh and enforces retention without deleting protected files.

## Prerequisites and Delivery

Before dependent implementation:

- **Isolated development server.** A separate demo Compose project with its own bind mounts and loopback port. The App Review 1.0 server, its data, and its screenshots are never touched.
- **Original fixtures.** Fixed, original fictional RSS feeds, scripts, recordings, and art, with a reviewed rights manifest and separate screenshot and edge profiles. Native ABS IDs are observed at runtime, never fabricated.
- **F0 catalog discovery.** Read-only discovery of how ABS creates podcast libraries and exposes shows and episodes. No endpoint is guessed.
- **F0p probes.** Isolated, transient play, progress, and played-state probes on the dev dataset, closed and reset afterwards, before any implementation that depends on them.
- **Sanitized capture.** Captures are sanitized in memory before anything is persisted, including headers, URLs, and error bodies, while keeping ID joins consistent.
- **Server versions.** Verify on the minimum supported 2.28 and on the version currently pinned in the compatibility manifest. Neither is claimed to be the latest ABS release.
- **Runtime gates.** The account boundary, migration-failure safety, and download/cover ownership land before the features that consume them.
- **PR 88.** [PR 88](https://github.com/clayreimann/SideShelf/pull/88) remains open for review and device validation; nothing here assumes or triggers its merge.

First increment delivery order. Each step is independently testable and keeps audiobooks green.

1. This docs slice.
2. Isolated fixtures, F0 discovery, and F0p probes with sanitized contracts. Each runtime contract is established before the implementation that depends on it.
3. Runtime gates: account commit boundary and atomic wipe, migration-failure gate, and download/cover ownership, before the features that consume them.
4. Two tracks that can proceed in parallel:
   - **Episode track:** episode schema and ingestion, then episode-aware progress and sessions, then playback and restore; played-state intent; manual episode downloads.
   - **Catalog track:** per-source catalog ingestion, then inclusion and the aggregated book Library tab, then Book Series guards, then the Podcasts tab (after the episode schema). The Series guards land before any podcast UI.
5. Show detail, episode actions, and Home, joining both tracks after playback, played state, and manual downloads are in place.
6. Maestro coverage and qualification on physical devices against 2.28 and the pinned current server.

**[Deferred]:**

1. Persistent Up Next and autoplay.
2. Device auto-download and retention.

## Out of Scope

- Adding, editing, or removing RSS subscriptions.
- External podcast search or discovery.
- Changing Audiobookshelf server-side feed acquisition schedules or retention settings.
- Google Cast; see [`docs/investigation/google-cast-support.md`](../../investigation/google-cast-support.md).
- CarPlay and Android Auto.
- Audio Browser production migration.
- Mixed audiobook/podcast Up Next.
- Video podcast playback.
- Guaranteed real-time background downloads at publication time.
- Episode bookmarks unless a stable server API is verified and separately approved.
- Cross-server library aggregation.
- Mixed book/podcast grids or a media-type filter on one library page.
- Merging podcast shows with book series by title, or routing podcasts through book-series screens.
- Podcast-specific skip-silence.

---

## Dependency on Public 1.2

Public 1.1 is intentionally a complete release on RNTP, including its deferred contract. Its stable media identity, queue ownership, episode-aware session behavior, and acceptance tests become the migration contract for public 1.2.

Public 1.2 may replace the native player, but it must not redesign podcast product semantics or make persisted queue/download data dependent on Audio Browser internals.
